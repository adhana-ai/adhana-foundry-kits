Read a rights register and say which options are about to lapse

One register snapshot, one model call, a field table — plus an expiry and a status counted afterwards, in pure code, from the values that came back. The count has an order: what starts the clock, which extensions were actually perfected, add the months consecutively from the clock start, then compare against the register’s own as-of date and the window. The register’s own status line and the clerk’s note are both on the page, and neither moves a day.

This proposes a worklist. It watches nothing. It reads one snapshot somebody else assembled, on the date that snapshot states. It does not poll, subscribe, schedule, alert, escalate, file, exercise, renew, lapse or clear anything, and nothing in it runs unattended. A qualified person reads the executed agreement. The counting rulebook shipped with this kit is illustrative and is not an authority — it was written for this kit and reproduces no option agreement, standard form, schedule or statute. Replace it with your own before you decide anything real by it.

The model reads; the code counts. The status above is the rulebook’s arithmetic over the extracted values, not the model’s own answer — a due date done in prose is a due date nobody can check. The model’s own status and expiry_date are in the field table beside it, and the gap between the two is this kit’s no-gold consistency diagnostic. escalate_now is a business condition: it fires when the counted status is anything other than live and the register still carries itself as live, because an option the file already shows as lapsed is a known loss and this one is on nobody’s report. not_determinable counts here too — treating a record nobody can date as a pass is the one thing a monitoring queue must never do. This is the kit’s own simplification, not a rights desk’s escalation policy — no company’s procedure was consulted, and none is reproduced.
