Trace one invoice and draft its payment-status reply

One vendor inquiry, one 4-stage record — match, approval, run inclusion, remittance — one model call, a traced stage and a grounded reply. The record is read in order: the true current stage is the first stage that is not cleanly complete, never whatever a downstream field happens to show.

This kit never releases a payment, changes a remittance detail, or commits to a date beyond the scheduled run — the reply is informational only, and any invoice with an open exception is flagged for AP review before it goes out. Every invoice is synthetic, generated at build time from a fixed seed — never a real vendor.
