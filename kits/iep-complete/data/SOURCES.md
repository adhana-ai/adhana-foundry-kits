# Where this corpus came from

**It was written here.** `tools/build_corpus.py` generates every education plan from a fixed seed
(`SEED = 20260822`), so the corpus is byte-identical on every rebuild and there is no third-party
data in this kit at all.

| | |
|---|---|
| source | generated by `tools/build_corpus.py`, seed `20260822` |
| dataset version | `iep-complete-2026-08-22-52plans` |
| licence | **MIT** — this repository's own licence |
| plans | 52, in `data/corpus/*.txt`, 125,347 bytes |
| gold | 52 rows in `data/gold.jsonl` |
| component rulebook | `data/rulebook.json` — **written for this kit**, see the warning below |
| pupils / schools / districts | invented reference codes, invented school and district names, invented notes, with no link to any real pupil, family, school, district, charter network or agency |

## ⚠︎ NO REAL PUPIL DATA, AND NOTHING RESEMBLING IT

This is a kit about a document that, in the real world, is one of the most sensitive records a
school holds. Nothing in this repository is one, and the corpus is built so that it could not be
mistaken for one:

- **There are no names.** A pupil is a reference code (`PUP-C61-3660`) and nothing else. No pupil,
  parent, teacher, therapist, case manager or reviewer is named anywhere. The case manager's note is
  signed by nobody, and the checklist is signed with a code.
- **There are no dates and no dates of birth.** Not on the plan, not in gold, not in the file names.
  The pupil's age appears as a bare number of years, or as the words "not stated", because whether
  the age is stated at all is one of the things this kit checks. That is the only personal-shaped
  field in the corpus and it is an integer between 6 and 18.
- **There is no disability category, no diagnosis and no eligibility label**, anywhere, tied to
  anybody. The plans state performance levels and goals in ordinary curriculum terms — reading
  fluency, written expression, organisation and task initiation — and nothing in the corpus says or
  implies why a pupil has a plan. This kit has no view on eligibility and cannot form one.
- **Every school and district name is a made-up compound** — Hollowbrook Middle School, Quillhaven
  Unified District. None is a real school, district, charter network or agency, and any resemblance
  to one is unintended and unresearched: the names were assembled from ordinary English place-words
  and no register of schools was consulted.
- **Every plan says so on its own first line.** The first section of every file is a
  `Synthetic Record` banner reading *"GENERATED SAMPLE — not a real pupil, school or district"* and
  naming the script and seed that wrote it. The corpus is obviously synthetic on its face, and it
  stays that way if a single file is ever copied out of this repository on its own.
- **Nothing was fetched.** No plan, template, form, sample or checklist was downloaded, scraped,
  anonymised or adapted from anywhere. There is no `_fetched/` directory in this kit because there
  was nothing to fetch.

⚑ **Two of those sections never leave your machine either.** `Synthetic Record` and
`School and District` are mapped by no field in `src/select.py`, so the union of the mapped sections
excludes them and they are never sent to a provider. `evals/check_labels.py` asserts both facts —
that they exist on every plan, and that no field maps to either — before any run may spend.

## ⚠︎ The component rulebook is invented and is NOT an authority

**`data/rulebook.json` was authored for this kit.** It reproduces **no** statute, **no** regulation,
**no** state or district plan template, **no** agency guidance and **no** published completeness
checklist. Nothing in it was copied from, derived from, or checked against any such document,
because none was consulted. No education authority, district, school, lawyer, advocate or
special-education professional has looked at it.

It is a small, deliberately readable construction whose only job is to make the *decision shape*
measurable: seven components, each with the elements that make it checkable, one of them conditional
on a fact about the pupil, and four states a component can be in. Several of its simplifications are
visibly not how a real plan review works, and the sharpest is named in the file itself — **the
transition age of 14 is a number this kit chose**, with no source and no reasoning behind it beyond
"the rule has to be conditional on something for the conditional case to be measurable at all".

**The real authority for any plan is the team that writes it, working to whatever rules actually
apply where they are.** This kit proposes a reviewer's worklist with the rulebook's own reasoning
and names what it could not determine. It never approves, signs, files or amends a plan, and nothing
in it writes, submits or dispatches anything. That sentence is on the kit's own UI, above the
answer, and not only here.

## Why an invented set of plans, when real ones exist

**Because a real education plan is the last document this repository should ever publish.** It names
a child, their family, their school, their difficulties and the professionals working with them. It
is exactly the kind of record that must not be scraped, anonymised or "adapted" into a public
corpus, and there is no public corpus of (plan, correct completeness verdict) pairs for a reason
that is not an accident.

Generating it also makes the label mechanical: gold's `plan_outcome` is the rulebook lookup run over
the same seven states the generator built the text from, never somebody's reading of the checklist.

## The mechanic: one call per plan, fourteen fields

Each plan states an identifier, a pupil reference, an age (or that the age is not stated), whether
the plan is a draft or already in effect, a section for each component the rulebook asks for, a
previous reviewer's checklist result, and a case manager's free-text note. The model extracts
fourteen fields — everything except the `Synthetic Record` banner and the `School and District`
section, which no field maps to and which are therefore never sent — including the seven it has to
judge and the outcome that follows from them. See `src/prompt.py`.

**The rulebook is sent with every call.** Measured on the worked example (IEP-0016): the system
prompt is 907 of 3,594 input tokens, the rulebook 983, the four state definitions 241, the field
schema 897, and the plan itself 566. The fixed prefix is 3,028 tokens — 84% — and it is
byte-identical on every call, which was measured on two different plans rather than assumed
(`results/tokens-p001-iep-complete.json` and `tokens-p002-iep-complete.json`).

## The rule, and the stopping order a reader gets wrong

```
decide(component_states, pupil_age):
    any REQUIRED component absent                     -> components_missing
    any REQUIRED component present-and-unmeasurable   -> not_measurable
    no age stated AND transition not present-complete -> undetermined
    otherwise                                         -> complete
```

Four things about that rule are stated to the model in full, because each is a reading a careless
reviewer falls into on its own — and each is measured on this corpus rather than asserted:

| | | measured here |
|---|---|---|
| **a section that is PRESENT is not a section that COUNTS** | a goal with no baseline, no criterion or no measurement method is a heading with prose under it. It passes a checkbox review and cannot be shown to have been met or missed | **32 component cells**, on **26 plans** |
| **ONE bad entry makes the whole component unmeasurable** | six sound goals and a seventh with no criterion is a component nobody can measure against, not a component that is 86 pct right. Sections are never scored on average — and on **5 plans** the section opens with a sound goal and breaks a later one | **5 plans**, asserted off the shipped text |
| **the conditional component depends on the PUPIL, not the plan** | below the rulebook's transition age the component is `not_required` whatever the plan contains, and a checker that counts seven headings raises a false defect on every younger pupil. Asserted directly: the same document read for an older pupil must come out `components_missing` | **5 plans**, and **14 component cells** in that state |
| **an unknown requirement is not an absent one** | with no age stated, `not_required` is never correct — the rulebook cannot say whether the component was required, and reports `undetermined` rather than guessing. And "no age" is *not* a shortcut for "undetermined": **3 plans** state no age and are still answerable, because a component they do carry is already defective | **5 undetermined**, **8 with no age** |

The rule lives in one function — `src/rulebook.py::decide()` — used to write gold, stated to the
model by `src/prompt.py`, and re-run over the model's own reply by `evals/judge.py`. Three readers,
one definition, so the corpus, the prompt and the diagnostic cannot drift about what an outcome
means.

## The planted ambiguity: two decoys, not one

**The checklist.** Every plan carries a previous reviewer's own tick-box result. On **18 of 52** it
claims every required component is present while the rulebook finds a defect. It is never an input
to anything — and all three claim values appear on both sound and defective plans, deliberately, so
that "copy the checklist" is not a correct shortcut this corpus would reward.

**The case manager's note.** `N_AMBIGUOUS = 21` puts a note from the wrong register on exactly 40%
of plans, in both directions:

- a plan with real defects carrying a reassuring note — *"Reviewed with the team; everything is in
  place and ready to sign."* (15 plans);
- a plan that is entirely sound carrying a note that reads like a problem — *"Something looked thin
  here — flagged for a second read before it goes out."* (6 plans).

Gold's `plan_outcome` is **never** derived from either. It is the rulebook lookup, run over the same
seven states the plan itself states.

`evals/check_labels.py` re-runs that lookup over every gold row before a run is allowed to spend,
and fails if any label disagrees with its own states — and separately asserts, for free and before
anything spends, that the free floor cannot reach the two states it is published as unable to reach.
A sibling kit earlier in this series shipped a floor whose keyword list fired on the register it was
written to ignore and mis-classified four records for days; that check is written into this kit's
gate from the start rather than found live.

## The composition is exact, then shuffled — not drawn per plan

Each of the ten buckets is a fixed **count**, shuffled by the seeded RNG, and every constructor is
asserted against the rulebook at build time — a constructor that quietly stops producing its own
bucket is exactly the defect an exact composition exists to prevent. The age bands, the checklist
claims, the note registers, the absent components and the second unmeasurable component are all
dealt exactly too.

| | |
|---|---|
| `complete` | 12 |
| — every required component present and measurable | 7 |
| — no transition section, and the pupil is below the threshold | 5 |
| `components_missing` | 15 |
| — exactly one required component absent | 7 |
| — two or three absent | 4 |
| — transition absent on a plan that needs it | 4 |
| `not_measurable` | 20 |
| — a goal with no baseline, no criterion or no measurement method | 8 |
| — a service line missing frequency, duration or location | 5 |
| — a measurement method with no reporting schedule | 4 |
| — a post-school goal with no steps under it | 3 |
| `undetermined` — no age stated and no transition content | 5 |
| component cells present-and-unmeasurable | 32 |
| component cells absent (5 written as a placeholder rather than omitted) | 26 |
| component cells `not_required` | 14 |
| plans whose checklist claims everything is present while the rulebook disagrees | 18 |
| plans carrying a note from the contradicting register | 21 (40%) |
| plans already in effect | 24 |
| not complete **and** already in effect — the worklist flag | 20 |

## The guardrail is a business condition, not a check on the model

`src/extract.py::compute()` puts a plan on the worklist when the outcome is anything other than
`complete` **and** the plan is already `in_effect`. A draft can simply be finished before it is
signed; the same finding on a plan already in effect means a pupil is being taught against a goal
nobody can measure, or a service with no frequency to deliver against. `undetermined` counts here
too — treating an unknown as a pass is the one thing a completeness check must never do.

⚠︎ **This is the kit's own simplification, not anybody's review policy.** No district procedure,
agency guidance or regulation was consulted, and none is reproduced. A real review queue weighs how
long the plan has left to run, which component is missing, whether the next meeting is already
booked and who has authority to reopen it.

## What it cannot tell you

⚠︎ **This kit checks and proposes only — it never approves, signs, files or amends a plan, and never
contacts anybody.** Every component state is an extracted field and `on_worklist` is a routing
signal; nothing here disposes of anything, and nothing here is a decision about a pupil.

⚠︎ **A run that scores well has agreed with `data/rulebook.json`, which is a much smaller claim than
being right about a real plan.** The graders measure whether the run applied the shipped rulebook.
They cannot measure whether the rulebook is correct, because the rulebook is this kit's own
construction — and on this subject the gap between "agrees with our invented list" and "is right
about a child's provision" is as wide as it gets on this site.

⚠︎ **It knows nothing about whether the plan is any GOOD.** Whether a goal is the right goal for
this pupil, whether a service is appropriate, whether a stated baseline is accurate, whether the
provision is enough — none of that is visible to a completeness check, and a plan can be perfectly
complete and completely wrong. Measurability is a floor, not a standard.

⚠︎ **An invented corpus contains the ambiguity we thought to plant and no others.** A real review
queue carries confusions this one does not attempt — a plan written across several documents, a goal
whose baseline sits in an attached assessment report rather than in the plan, a service delivered
under a different name from the one committed to, handwritten amendments, a section that contradicts
another section, and a measurement method that is named and does not exist. A model that clears this
corpus has cleared what this corpus tests, not every way a plan review can go wrong. **This kit's
own weakest construction is named on the published page**: two of the accommodations lines end in a
phrase that reads like a setting and is not one, and both of the scored run's only two errors are
there.
