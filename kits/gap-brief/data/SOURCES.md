# Where this corpus came from

**It was written here.** `tools/build_corpus.py` generates every cycle, every line item's three
plan views, every planning note and the gold gap list from a fixed seed (`SEED = 20260818`), so
the corpus is byte-identical on every rebuild and there is no third-party data in this kit at all.

| | |
|---|---|
| source | generated by `tools/build_corpus.py`, seed `20260818` |
| licence | **MIT** — this repository's own licence |
| cycles | 40, in `data/cycles.jsonl` — each carrying 5 line items across three plan views |
| notes | 40 rows in `data/notes.jsonl` — one planning-notes log per cycle |
| gold | 40 rows in `data/gold.jsonl` — every item's materiality, true cause and traceable citations |
| formats | jsonl (cycles, notes, gold) |

## Why an invented planning corpus, when real ones exist

**Because a real one cannot be published at all.** A real demand/supply/financial reconciliation
names real SKUs, real committed volumes and real revenue numbers — exactly the material a business
will not let leave the building, on top of being the kind of internal planning correspondence
nobody signs an MIT licence over. There is no public corpus of paired (three plan views, planning
notes, adjudicated gap cause) for the same reason there is no public corpus of internal budget
reconciliation threads.

**Nothing in here refers to a real company.** Every business unit, category label, period and
planning-note line is invented; no row here states a real commercial figure.

## The job is generic; the flavour is not

This kit's actual job — reconcile three independently-maintained numeric plan views of the same
underlying reality, itemize every material gap with a quantified impact and a probable cause
traced to real source lines, and draft the meeting brief — applies to any set of three plans that
are supposed to describe the same thing but are each maintained by a different team: a
demand/supply/financial plan is one instance, a budget/forecast/actuals set or a hiring-plan/
headcount-budget/actual-headcount set are others. This corpus flavours it as a retail-style
sales-and-operations-planning cycle — demand plan, supply plan, financial plan, in dollars, across
synthetic product categories and regions — because that is the scenario the kit's originating use
case names. Point `tools/build_corpus.py` at your own three plan views and your own line items and
the pipeline — `src/segment.py`, `src/pack.py`, `src/prompt.py` — does not change.

## Seven scenarios, planted so completeness, cause-tagging and honesty are all worth telling apart

| scenario | what it is | cause the model should reach |
|---|---|---|
| `clean` | all three views agree within ordinary noise (±3%). Not itemized. | n/a — not material |
| `timing_lag` | one view hasn't been refreshed since a change the others reflect | `timing_lag`, traceable |
| `assumption_mismatch` | two views were built on different stated assumptions | `assumption_mismatch`, traceable |
| `data_entry_error` | a transcription/unit mistake moved one view | `data_entry_error`, traceable |
| `scope_mismatch` | one view rolls in a sub-line another excludes | `scope_mismatch`, traceable |
| `unknown_gap` | a real, material gap — the notes do not explain it | `unknown`, correctly unresolved |
| `missing_view` | one of the three views was never submitted this cycle | `unknown`, plus a mandatory missing-view caveat |

`src/segment.py::MATERIALITY_PCT = 12.0` is a stated judgement, not fitted to this corpus after
the fact — the same honesty `param-drift`'s and `data-reconcile`'s own thresholds state. Clean
items' noise band (±3%) and defect items' shift band (18–42%) were sized in `tools/build_corpus.py`
to sit cleanly on either side of it; `tools/build_corpus.py --n-cycles 40`'s own tally line prints
the resulting scenario counts on every rebuild so the split can never silently drift from what
this file claims.

## The gold cause is never inferred by the pipeline's own code

`tools/build_corpus.py` decides each item's scenario, its shifted view and (for the four
traceable causes) its exact two explanatory notes lines at generation time — all before
`src/segment.py::align` ever runs. The pipeline recomputes materiality independently, from the
plan-view numbers alone, using the identical threshold the generator was sized against; it never
reads `data/gold.jsonl`. How well a model's cause tag matches the gold cause is therefore a real,
measured question — never a tautology.

## What this corpus does not test

- **One static cycle per item, not a rolling history.** A real deployment would see the same item
  recur cycle over cycle, sometimes still gapped from last time; this corpus judges every cycle
  independently.
- **One planted cause per gap.** A real gap can have two compounding causes at once; this corpus
  always plants exactly one (or none, for `unknown_gap`).
- **Two items in the same cycle sharing a root cause.** Every item's scenario is drawn
  independently in `tools/build_corpus.py`.
- **A cause outside the five-member vocabulary.** A real reconciliation meeting will eventually
  name a cause this kit's fixed list does not carry; extending it is a `src/rubric.py` change plus
  new template notes in `tools/build_corpus.py`, not a prompt tweak alone.
