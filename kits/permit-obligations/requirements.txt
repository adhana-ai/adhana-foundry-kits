# NOTHING. This kit is Python standard library, end to end.
#
# It was not written to be minimal for its own sake -- docs-qa has one dependency, pypdf, and that
# dependency earns its place because PDF text extraction is genuinely not something to hand-roll.
# This corpus is generated in-process by tools/build_corpus.py, the rulebook is a JSON file read
# with `json`, all of the date arithmetic is `datetime.date` plus `timedelta`, and the model is
# reached over urllib in src/adapters/__init__.py rather than through any vendor SDK -- so a forker
# runs this on whichever key they already hold, instead of installing a client for a vendor they
# will never call. There was nothing left to add.
#
# ⚠︎ AND IN PARTICULAR, NO SCHEDULER. A monitoring kit is the one place a reader might expect a
# cron library, a queue or a job runner in this file, and there is none, because this kit does not
# monitor: it reads one snapshot somebody else assembled and proposes a worklist. A dependency here
# would be the first thing to suggest otherwise.
#
# ⚠︎ A requirements file naming a package the code never touches is a small lie that costs a forker
# an install and teaches them the kit is bigger than it is. If you add a line here, something under
# src/ or evals/ must import it.
