# Where this corpus came from

**It was written here.** `tools/build_corpus.py` generates every pre-load check sheet from a fixed
seed (`SEED = 20260822`), so the corpus is byte-identical on every rebuild and there is no
third-party data in this kit at all.

| | |
|---|---|
| source | generated by `tools/build_corpus.py`, seed `20260822` |
| dataset version | `cargo-compat-2026-08-22-55sheets` |
| licence | **MIT** — this repository's own licence |
| sheets | 55, in `data/corpus/*.txt`, 30,608 bytes |
| gold | 55 rows in `data/gold.jsonl` |
| compatibility matrix | `data/matrix.json` — **written for this kit**, see the warning below |
| tanks / terminals / inspector notes | invented identifiers, invented terminal and berth names, invented notes, with no link to any real terminal, operator, carrier or shipment |

## ⚠︎ The compatibility matrix is illustrative and is NOT an authority

**`data/matrix.json` was authored for this kit.** It reproduces **no** commercial, industry-body or
proprietary compatibility chart, **no** carrier's or terminal operator's own prior-cargo list, and
**no** regulatory schedule. Nothing in it was copied from, derived from, or checked against any such
document, because none was consulted.

It is a small, deliberately readable construction whose only job is to make the *decision shape*
measurable: a class lookup, a reactive-pair check, a grade-driven predecessor ban with a look-back
depth, and a minimum cleaning standard that only a certificate can satisfy. Several of its
simplifications are visibly not how a real terminal works, and are named as such in the file itself
— most obviously the single ordered "wash ladder", which pretends that a detergent wash, a caustic
boil and a steam-and-dry are four rungs of one scale when in reality they are different regimes for
different residues.

**The real authority for any load is the incoming product's safety data sheet, the tank's actual
cleaning record, and a competent person's assessment.** This kit proposes a verdict with its
reasoning and names what it could not determine. It never authorises a load, and nothing in it
writes, dispatches, releases or clears anything. That sentence is on the kit's own UI, above the
answer, and not only here.

**Every cargo name is an ordinary generic chemical or oil name** — methanol, toluene, sodium
hydroxide solution, refined sunflower oil. No trade name, brand, supplier, carrier or terminal
operator is named anywhere in this kit.

## Why an invented set of check sheets, when real ones exist

**Because a real pre-load check sheet is not something this repo can publish either.** It names a
real tank on a real berth, a real customer's product, a named inspector's own remark, and a real
carrier's cleaning history. There is no public corpus of (pre-load sheet, correct verdict) pairs,
for the same reason there is no public corpus of bank statements or certificates of analysis.

Generating it also makes the label mechanical: gold's `verdict` is the matrix lookup run over the
same five values the sheet states, never somebody's reading of the inspector's note.

## The mechanic: one call per sheet, ten fields

Each sheet states a tank, its terminal and berth, the incoming product, the grade it is being
loaded as, the prior cargo, the cargo two back, the wash the **tank log** claims was performed, what
the cleaning **certificate** actually covers, whether the product has already gone in, and the
terminal inspector's own free-text note. The model extracts ten fields — everything except the
terminal and berth, which no field maps to and which is therefore never sent — including the one it
has to decide: the pre-load verdict. See `src/prompt.py`.

**The matrix is sent with every call.** A compatibility decision is a lookup, and a model cannot
look up a table it has never been shown. `src/prompt.py::matrix_block()` renders `data/matrix.json`
into the prompt rather than restating it in prose, so the instructions and the gold labels cannot
drift apart about the same table. Measured on the worked example: 473 of 2,100 input tokens (23%)
are the matrix.

## The rule, and the stopping order a reader gets wrong

```
verdict(incoming_product, grade, prior_cargo, two_back_cargo, wash_certified_for):
    prior cargo not recorded, or a cargo not in the matrix  -> undetermined
    prior class + incoming class is a reactive pair          -> refuse   (no cleaning clears it)
    any cargo within the grade's LOOK-BACK DEPTH is banned   -> refuse   (cleaning does not cure a ban)
    certified wash >= minimum for prior class at this grade  -> accept
    otherwise                                                -> clean_then_load
```

Four things about that rule are stated to the model in full, because each is a reading a careless
reader falls into on its own — and each is measured on this corpus rather than asserted:

| | | measured here |
|---|---|---|
| **a ban is not a cleaning problem** | methanol before a food-grade load is water-miscible, non-reactive and trivially rinsed out. It is banned anyway, and no certificate makes it acceptable | **3 sheets** |
| **the certificate governs, not the tank log** | `wash_performed` is what the log claims; `wash_certified_for` is what a certificate covers. When they disagree the tank is credited with the certificate's regime, and an uncertified tank is credited with no wash at all | **8 sheets**, the log always claiming the more thorough one |
| **food grade and high purity read TWO cargoes back** | an entirely innocuous prior cargo can sit in front of a banned one. Read only the prior cargo and these sheets look like a clean `accept` — asserted directly in `evals/check_labels.py`, not hoped for | **5 sheets** |
| **the residue that sounds worst often rinses out** | caustic, acid and hypochlorite heels are water-soluble and sit at `water_rinse`. What is expensive to clean here is fat and hydrocarbon, not corrosives | **6 sheets** |

The rule lives in one function — `src/matrix.py::decide()` — used to write gold, stated to the model
by `src/prompt.py`, and re-run over the model's own reply by `evals/judge.py`. Three readers, one
definition, so the corpus, the prompt and the diagnostic cannot drift about what a verdict means.

## The planted ambiguity: the verdict is a lookup, and the note disagrees with it

`N_AMBIGUOUS = 22` puts an inspector's note from the wrong register on exactly 40% of sheets:

- a tank that must be refused or cleaned, carrying a relaxed note — "Tank presented clean and dry,
  no odour on opening. Nothing of concern.";
- a tank that is genuinely fine, carrying a note that reads like a problem — "Faint odour still
  present at the hatch -- escalated to the duty superintendent."

Gold's `verdict` is **never** derived from the note. It is the matrix lookup, run over the same
values the sheet itself states.

`evals/check_labels.py` re-runs that lookup over every gold row before a run is allowed to spend,
and fails if any label disagrees with its own values — and separately asserts that every note
template classifies to the register it was written as, against the free floor's own keyword list,
before anything may spend. A sibling kit earlier in this series shipped a keyword that fired on a
negation inside a relaxed note and mis-registered four records for days; that check is written into
this kit's gate from the start rather than found live.

## The composition is exact, then shuffled — not drawn per sheet

Each of the eight buckets is a fixed **count**, shuffled by the seeded RNG, and every constructor is
asserted against the matrix at build time — a constructor that quietly stops producing its own
bucket is exactly the defect an exact composition exists to prevent.

| | |
|---|---|
| `accept` | 16 |
| — an alarming-sounding corrosive heel that genuinely rinses out | 6 |
| `clean_then_load` | 15 |
| — the certificate covers **less** than the tank log claims | 8 |
| — the tank is simply undercleaned, and its paperwork agrees | 7 |
| `refuse` | 18 |
| — a reactive heel/product pair | 6 |
| — a banned predecessor (3 of them methanol before food grade) | 7 |
| — a banned cargo **two back**, behind an innocuous prior one | 5 |
| `undetermined` — no prior cargo recorded | 6 |
| inspector note from the contradicting register | 22 (40%) |
| already loaded | 24 |
| not clear-to-load **and** already loaded — the hold flag | 19 |

## The guardrail is a business condition, not a check on the model

`src/extract.py::compute()` raises a hold when the verdict is anything other than `accept` **and**
the product has already gone into the tank. A pending load can simply be cleaned or refused before
it goes in; the same verdict on a tank already loaded means product is sitting on a residue it
should not be sitting on. `undetermined` counts here too — treating an unknown as a pass is the one
thing a pre-load check must never do.

⚠︎ **This is the kit's own simplification, not a terminal's real quarantine policy.** No operator's
procedure, industry code or regulatory rule was consulted, and none is reproduced. A real terminal
weighs how much product is in the tank, whether it can still be diverted, what the receiving
customer's own specification says, and who has authority to release it.

## What it cannot tell you

⚠︎ **This kit checks and proposes only — it never authorises a load, never releases a tank and
never contacts anybody.** `verdict` is an extracted field and `needs_hold` is a routing signal;
nothing here disposes of anything.

⚠︎ **A run that scores perfectly has agreed with `data/matrix.json`, which is a much smaller claim
than being right about a real tank.** The graders measure whether the run applied the shipped
matrix. They cannot measure whether the matrix is correct, because the matrix is this kit's own
construction.

⚠︎ **An invented corpus contains the ambiguity we thought to plant and no others.** A real pre-load
queue carries confusions this one does not attempt — a heel of unknown volume rather than a named
cargo, a cargo carried under a trade name that maps to several compositions, a cleaning certificate
issued by a party with an interest in the answer, a tank with an internal coating that changes what
a residue does, a partial discharge leaving more heel than a full one, and a product whose own
specification is stricter than any predecessor rule. A model that clears this corpus has cleared
what this corpus tests, not every way a pre-load check can go wrong.
