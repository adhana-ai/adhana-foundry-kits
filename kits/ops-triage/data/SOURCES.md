# Where this corpus came from

**It was written here.** `tools/build_corpus.py` generates every event from a fixed seed
(`SEED = 20260813`), so the corpus is byte-identical on every rebuild and there is no third-party
data in this kit at all. No clock is ever read — the stream starts at a fixed instant and every
timestamp is arithmetic from it.

| | |
|---|---|
| source | generated by `tools/build_corpus.py`, seed `20260813` |
| licence | **MIT** — this repository's own licence, verified against `LICENSE` at the repo root on 2026-08-13 |
| events | 15,189 in `data/events.csv` |
| windows | 240 in `data/labelled.jsonl` — 20 page, 220 hold |
| stream | 20 hours, 8 services, cut into 5-minute buckets |
| formats | csv, jsonl |

## Why invented logs, when every company on earth has real ones

**Because real production logs cannot be published at all**, and that is not a licence
technicality. They carry hostnames, internal service names, customer and session identifiers, and
the shape of somebody's private network — and the interesting lines, the ones an incident actually
turns on, are precisely the ones carrying the most identifying detail. Scrubbing hard enough to
make a log stream publishable removes the thing this kit measures.

There is no public corpus of labelled production alerts for the same reason. So a synthetic stream
is not the convenient choice here; it is the only kind of alert-triage corpus a stranger can clone
and re-run without signing anything.

**Nothing in here refers to a real system.** The service names are generic (`checkout`, `auth`,
`payments`, `orders`, `billing`, `search`, `postgres`, `deploy`), there are no hostnames, no IP
addresses and no identifiers of any kind that could belong to anybody.

## What it cannot tell you

⚠︎ **An invented corpus contains the failure modes we thought to plant and no others.** That is a
real limit and it is on the published report as well as here. A live event stream carries kinds of
noise this set does not, and — the bigger one — **its incidents are not politely one per window**. A
real outage starts mid-bucket, overlaps three other things, and is preceded by a week of unrelated
grumbling.

⚠︎ **The five-minute bucket is a product decision this corpus bakes in.** Widen it and the retry
storm's recovery line falls inside the window, so the correct answer for that window flips from
page to hold. Narrow it and the cascade splits into windows that each look like a separate outage.
The labels are true *for a five-minute cut* and for no other.

## The traps, and why each one is in here

Six kinds, counted and asserted by `tools/build_corpus.py::audit`. A census no code checks is a
census that goes wrong: a sibling kit in this repo shipped 117 accidental collisions under a
comment claiming one.

**Windows that SHOULD wake somebody** — a triager that holds these misses an outage:

| trap | what it looks like | windows |
|---|---|---|
| `quiet-killer` | one WARN: a certificate expiring, a WAL slot filling a disk, an unacknowledged settlement file | 8 |
| `cascade` | postgres FATAL, then five services failing on one root cause, 200+ lines | 6 |
| `silence` | a service that emitted **nothing** while it had been logging steadily | 6 |

**Windows that should NOT** — a triager that pages on these trains a rotation to ignore the pager:

| trap | what it looks like | windows |
|---|---|---|
| `flapping` | a health check timing out every six seconds for nine days — 47 errors, never meant anything | 40 |
| `retry-storm` | 48 backoff errors, working exactly as designed, recovering inside the window | 18 |
| `deploy` | errors that spike immediately after a release line and stop on their own | 12 |
| `quiet` | ordinary traffic, some of it carrying an ordinary WARN | 150 |

⚑ **The two the free rules cannot reach are the reason the kit exists**, and `evals/baseline.py`
measures it over **49 settings across four floors** rather than asserting it:

- **`quiet-killer` is unreachable by anything in `src/rules.py`.** One WARN line — no count
  threshold reacts to one line — and the text is ordinary English about a certificate, so there is
  no alarming word to match. Nothing is on fire yet. It is a fuse, and it is lit.
- **`silence` cannot be matched by a regex at all**, because the signal is the *absence* of lines.
  It is reachable only because `src/window.py` compares the window against its history and computes
  the fact in code first — which is the division of labour this whole kit argues for.

The measured result: the strongest free floor makes **0 false pages and misses 8 of 20 incidents**,
and **no setting of any floor handles all six traps.** The one it never reaches is `quiet-killer`.
