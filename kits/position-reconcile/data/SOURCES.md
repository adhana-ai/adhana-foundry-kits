# Where this corpus came from

**It was written here.** `tools/build_corpus.py` generates every break record from a fixed seed
(`SEED = 20260821`), so the corpus is byte-identical on every rebuild and there is no third-party
data in this kit at all.

| | |
|---|---|
| source | generated by `tools/build_corpus.py`, seed `20260821` |
| licence | **MIT** — this repository's own licence |
| records | 55, in `data/corpus/*.txt` |
| gold | 55 rows in `data/gold.jsonl` |
| accounts / securities | invented account numbers and invented security names, sampled without any link to a real account or issuer |

## Why an invented set of position breaks, when real ones exist

**Because a real reconciliation break is not something this repo can publish either.** It names a
real account, a real custodian relationship and a real position — financial data tied to a real
client. There is no public corpus of (position break, operations-analyst-confirmed true/explainable
classification) pairs, for the same reason no public corpus of bank statements or pay stubs exists.

**Nothing in here refers to a real account, custodian or security.** Every account number, security
identifier and memo is invented; none states a real position or a real firm's reconciliation.

## The mechanic: one call per break, ten fields

Each record gives the model an account/security header, the internal and custodian quantities, how
many business days the break has been open, and the operations team's own reconciling memo. The
model extracts all ten fields, including whether the memo describes a genuine, unresolved
discrepancy or a benign, explainable timing difference. See `src/prompt.py`.

## The planted ambiguity: read what happened, not which words appear

The eval this kit exists to run is whether a model classifies a break by what the memo actually
says happened, or by which register of words it uses. `AMBIGUOUS_FRACTION = 0.40` of this corpus's
records are written against type on purpose:

- a **true break** whose memo still says "pending T+2 settlement" — the ORIGINAL explanation,
  now stale, because the settlement date has passed with no confirmation and no correction filed;
- an **explainable, resolved** item whose memo opens with alarming language ("URGENT",
  "mismatch flagged") despite being fully accounted for by its own final sentence.

Gold always records the TRUE classification, derived from which generator branch produced the
memo — never re-derived from a scorer's or a model's own reading of the memo's surface tone.

## The un-flagged aged true break is the safety-critical case

`src/extract.py::compute()` fires `needs_review` when a break is BOTH classified `is_true_break:
yes` AND older than `AGING_THRESHOLD_DAYS = 3` business days — **this kit's own stated policy, not
a real firm's documented SLA**; the atlas facet sheet this kit is built from explicitly notes "no
formal month-end SLA exists today" for this row. 25 of this corpus's 55 records should be flagged.
`evals/judge.py` reports recall on this figure as its own named figure, never folded into a generic
accuracy score.

## What it cannot tell you

⚠︎ **This kit reconciles and flags only — it never posts an adjusting entry.** Per this row's
facet sheet: "no adjusting entry posts without the named operations supervisor's approval." Every
break this kit flags is routed to a person; this kit never corrects a position itself.

⚠︎ **`AGING_THRESHOLD_DAYS = 3` is one kit's own simplification, not a cited regulatory or
firm-specific SLA.** A real reconciliation team's aging policy, escalation thresholds and approval
routing (who signs off above what dollar impact) are operator/firm-specific and unresolved in this
kit's own source facet sheet — stated plainly here so nobody mistakes this number for a real
published standard.

⚠︎ **An invented corpus contains the ambiguity we thought to plant and no others.** A real
reconciliation queue carries confusions this one does not attempt — a break that is a genuine
timing difference on ONE date and becomes a true break only after failing to resolve by the next
cycle, a security identifier mismatch that looks like a quantity break until the identifiers are
reconciled first, a custodian feed that arrives late and creates a false break for every position
in the account. A model that clears this corpus has cleared what this corpus tests, not every way
a real reconciliation break can go wrong.
